JOBDA 행동 리포트

이 리포트는 집계 수치만 담고 있습니다 — 개인 식별 정보(이름·이메일·사용자 ID·IP)는 포함되지 않습니다. 원본 로그 보존 기간에 따라 최근 약 5일 구간을 다룹니다.

핵심 요약

    월간 요약

    월 단위 집계. 기간을 선택해 보세요.

    용어 설명 (ⓘ 지표가 헷갈릴 때)
    • 방문(페이지뷰) — 페이지가 열린 총 횟수. 한 사람이 5번 열면 방문 5.
    • 세션 — 접속부터 이탈까지 한 묶음(한 번의 방문). 한 사람이 오전·오후 접속하면 세션 2.
    • 순 사용자(UV) — 중복 제거한 사람 수. 로그인 사용자는 userSn, 비로그인은 세션 기준으로 셈. (그래서 방문·세션보다 항상 작음)
    • 신규 가입 — 그 기간 회원가입을 완료한 수.
    • 검색 — 검색을 실행한 총 횟수.
    • 커리어메모리 전환율 — 커리어메모리 방문자(순 사용자) 중 노트 저장 또는 자료 업로드를 1회 이상 한 사람의 비율.
    • ※ 월간 순 사용자는 그 달 전체 기준 중복 제거값이라, 일별 순 사용자를 더한 값과 다릅니다(같은 사람이 여러 날 접속).

    3 · 로켓지원 — 단계별 진행 (교정판)

    지원건(사용자×공고) 단위로, 각 단계는 "그 단계 이상까지 도달한 지원건 수"입니다. 이벤트 수가 아니라 지원건 도달 여부로 세어 퍼널이 단조 감소(monotonic)합니다. 최종 제출은 사용자×공고 유니크 = 크레딧 차감 실제 건수와 일치합니다.

    로켓지원 단계별 퍼널

    지원건 도달 수 · 직전 단계 대비 전환율 (자동입력은 선택 단계라 gate에서 제외)

    4 · 로켓지원 최종 제출 내역

    기간 내 로켓지원 최종 제출(ROCKET_SUBMIT) 전체. 개인 식별자 없이 공고 단위로 집계했고, 기업·공고명은 페이지 제목에서 추출했습니다.

    제출 내역 (일자 순)

    JD 확정 제출이 일어난 공고 상세 페이지 제목에서 직접 확인 · 세션추정 목록/캘린더에서 제출되어 같은 세션의 가장 가까운 JD 방문으로 역추적 · 주의 신뢰도 낮음 또는 내부 테스트 의심 · 미확인 JD 방문 기록이 없어 해석 불가 (공고번호로 ATS 조회 필요)

    데이터 출처: jobda DB의 tracking_daily_stat / tracking_user_daily_stat / tracking_log / search_log (읽기 전용 집계 조회). 순 사용자는 사용자 ID 기준이며 비로그인 방문은 세션 단위로 계산. "완성률"은 기간 내 커리어메모리 방문자 중 노트 저장 또는 자료 업로드를 1회 이상 수행한 비율. 자동입력→섹션 검토 구간의 100% 초과 전환은 자동입력을 건너뛰고 검토로 진입한 사용자가 있어서 생기는 실제 수치.
